# تطبيق العلم — اتساق الوظائف وتجربة iOS، 6 سبتمبر 2026

الاتجاه المعتمد: تطابق الخصائص والوظائف مع الويب، وتصميم أصلي سلس للتطبيق ضمن هوية العلم. يحل هذا التقرير محل تفسير المطابقة البصرية السابق. التنفيذ محلي ولم يُنشر للخادم أو المتجر.

## القرار التصميمي

هوية العلم: خلفية #faf9f5، سطح أبيض #ffffff، حبر #141c24، كحلي #1a4282، رملي #f3efe8، ولمسات السلاسل المعتمدة. Alexandria للعناوين وIBM Plex Sans Arabic للنصوص، مع ألوان داكنة تكيفية ودعم تكبير خط النظام. محاذاة عربية إلى بداية السطر.

الرئيسية مكتب قراءة يومي: عنوان صدارة واضح، صورة، مقتطف، حفظ ومشاركة؛ ثم مدخل موجز مستقل وآخر المواد. اختيار «وراء الخبر» يكشف السياق والأرشيف، و«مرئي وبيانات» يكشف الإنفوجرافيك والأرقام والفيديو. لا تُنسخ قائمة الموقع أو تذييله داخل تغذية القراءة.

```text
[شعار العلم                         محفوظات / إشعارات]
[التاريخ] [عاجل إن وُجد]
[اليوم | وراء الخبر | مرئي وبيانات]
[عنوان الصدارة / الصورة / مقتطف / قراءة وحفظ ومشاركة]
[موجز العلم → شاشة قراءة واستماع]
[آخر المواد]
[الرئيسية | استكشف | البحث | لك أنت | حسابي]
```

مراجعة الاتجاه: بدلاً من تكرار بطاقات مؤطرة لكل محتوى، الصدارة مفتوحة بلا إطار، والمواد صفوف قراءة؛ الاستكشاف حسب الموضوع في شبكة هادئة، والسلاسل تحتفظ بطيف هويتها. التركيز على ترتيب المحتوى وسهولة الوصول، دون حركات تلقائية جديدة. يبقى كل تبويب محتفظًا بمكدس تنقله.

## ما تغير وظيفيًا

- «استكشف» يوفر الأقسام التسعة والسلاسل والوسائط. الأقسام والسلاسل تفتح أرشيفًا أصليًا مرقّمًا داخل التطبيق، بدل صفحة Safari أو تحميل تغذية مقيدة.
- `GET /api/mobile/v1/browse` يستخدم `pageBySection` و`pageBySeries` نفسيهما المستخدمين في الويب، مع العدد الكامل والصفحة التالية وبطاقات بلا متن. التكرار بين الصفحات يُزال في العميل.
- الحفظ والمشاركة من الصدارة وصفوف المواد، مع دعم مخزن المحفوظات القائم ومزامنته حسب الحساب.
- الاستفتاء السابق كان محليًا بثلاث إجابات مختلفة. استُبدل بخدمة `/api/content/interactions` الحالية: الإعجاب وسؤال الختام بخياري الويب ونتائج الخادم. لا تظهر عملية ناجحة حتى يرجع تأكيد الخادم، ولا تُرحّل أصوات الجهاز القديمة. تُفصل حالة الشاشة عند تبديل الحساب.
- زر تشغيل للفيديو والبرنامج الصوتي يفتح المادة الأصلية في Safari المضمّن. رابط المادة الأصلية ومصادرها متاح من القارئ.
- روابط من نحن والتواصل والنشرة وإدارة الحساب موجودة في الحساب بدلاً من تذييل الرئيسية.
- امتداد `presentation` السابق باقٍ: اختيار محتوى مشترك مع الويب دون فرض ترتيب واجهته. الكاش القديم قابل للقراءة؛ الميزات التي تتطلب API جديدًا تحتاج نشره أولًا.

## مصفوفة الوظائف وحدود التنفيذ

| الوظيفة | الحالة في التطبيق | حد التحقق |
|---|---|---|
| المحتوى والهوية والسلاسل | المصدر والعقود المشتركة، خط وشعار رسميان | API محلي ومراجعة المحاكي |
| أرشيف الأقسام والسلاسل | شاشات أصلية وترقيم كامل | صفحتان من السياسة وأبسط والفيديو والإنفوجرافيك؛ فتح السياسة فعليًا |
| البحث | شاشة أصلية ومحرك بحث الأرشيف | جُرب بحث التنجستن في الفحص السابق؛ لا تغيير في المحرك بهذه الجولة |
| الحفظ والمشاركة | من البطاقة والقارئ، مشاركة نظامية | حفظ وإلغاء من بطاقة؛ لا إرسال مشاركة خارجية |
| الإعجاب والاستفتاء | عقد التفاعل الفعلي وخيارات الويب | تحميل القارئ؛ اختبار عميل Swift مع خادم وهمي، دون إرسال تصويت تجريبي إلى الإنتاج |
| الموجز الصوتي | قراءة واستماع عبر خدمة الويب | لم يُولّد صوت أثناء الفحص |
| قراءة المقال صوتيًا | AVSpeechSynthesizer محلي قائم | يختلف محرك الصوت عن الويب، ولم يُبدّل في هذه الجولة |
| البودكاست والفيديو والمحتوى الغني | الوصول الكامل عبر Safari المضمّن | مشغل أصلي للبودكاست والفيديو لم يُبنَ بعد؛ متن API نصي وقد لا ينقل الروابط والتضمينات |
| الحساب والاهتمامات ولك أنت | التنفيذ القائم؛ مدخل إدارة الحساب العام | لم تُختبر دورة دخول ومزامنة متعددة الأجهزة في هذه الجولة |
| الصفحات العامة والنشرة | روابط ضمن الحساب | النماذج تظل على الموقع |
| الإشعارات والدفع | لم تُوسّع ضمن هذه الجولة | APNs والدفع وجهاز فعلي ليست ضمن أدلة النجاح |

هذه ليست شهادة اكتمال لجميع وظائف المنتج. أهم العمل المتبقي للتكافؤ الأصلي الكامل: مشغل البودكاست/الفيديو، نقل الروابط والتضمينات إلى القارئ الأصلي، مقارنة تجربة الصوت، واختبار الحساب والمزامنة الفعليين قبل الإصدار.

## التحقق

- نجح بناء SwiftUI على Xcode 26.6 ومحاكي iPhone 17e / iOS 26.5.
- نجح TypeScript وESLint للملفات الخلفية المعدلة و`git diff --check`.
- 14 اختبارًا لعقود المحتوى والخرائط والأرشيف، واختبار إضافي يشغّل كود `APIClient.swift` نفسه على خادم وهمي للتحقق من حفظ كوكي التفاعل، إرسال `liked: false` و`answer: 0`، وتلقي فشل 503 كخطأ.
- استجاب الأرشيف بصفحتين، 18 مادة لكل صفحة، دون تكرار بينهما: سياسة 4603، أبسط 5047، فيديو 687، إنفوجرافيك 1692. هذه أعداد وقت الفحص، والمسار غير المعروف أعاد 404.
- فحص بصري للرئيسية واستكشف وأرشيف السياسة والقارئ، والوضع الداكن لاستكشف، وأكبر حجم نص لإمكانية الوصول. الحفظ وإلغاء الحفظ والرجوع نفذت من الواجهة.
- لقطات الجولة في `.codex/visualizations/2026/09/06/01a074e4-7ffc-7260-9dff-917ace49e2be/native-ios` ضمن مجلد المستخدم.
- لا نشر للخادم، لا TestFlight، لا متجر، لا اختبار دفع أو تصويت إنتاجي. نجاح البناء لا يغطي هذه المسارات.

## إعادة الفحص

```sh
NEXT_DIST_DIR=tmp/ios-parity-next npm run dev -- --port 3106
xcodebuild -project ios/Elm.xcodeproj -scheme Elm -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 17e' \
  -derivedDataPath /tmp/alelm-ios-native CODE_SIGNING_ALLOWED=NO build
node --test tests/mobile-api.test.mjs tests/mobile-home-presentation.test.mjs tests/mobile-browse.test.mjs tests/ios-api-contract.test.mjs
```

عند تشغيل المحاكي استخدم `SIMCTL_CHILD_ELM_API_ORIGIN=http://127.0.0.1:3106`. العضوية والتفاعل يظلان على أصل الجلسة الإنتاجي نفسه؛ اختبار الإرسال أعلاه يستخدم خادمًا وهميًا فقط.
