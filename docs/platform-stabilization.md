## ترتيب التفعيل

1. مراجعة هذا الفرع وCI، ثم نسخة اختبار من قاعدة الإنتاج. لا تستخدم `db:push` لهذه الحزمة.
2. أخذ نقطة استعادة/نسخة احتياطية من الإنتاج وحفظ مفاتيح التشغيل في مدير الأسرار. تجربة الاستعادة المحلية لا تُثبت استعادة بيانات الإنتاج أو الوسائط.
3. إيقاف كتابات المحررين والعامل المجدول القديم خلال نافذة التفعيل؛ الكود القديم لا يعرف قفل الإصدارات. الترحيلات إضافية، لكن نشر القديم والجديد معًا يضعف ضماناتها.
4. توفير اتصال مباشر في `DATABASE_URL_UNPOOLED` ببيئة الترحيل، ثم:
   ```bash
   npm run db:migrate              # عرض فقط
   npm run db:migrate -- --apply   # لا يُنفذ إلا في البيئة المعتمدة
   npm run db:check               # قراءة فقط؛ يجب أن تكون ready: true
   ```
   المشغّل يتحقق من أعمدة مخطط الأساس قبل تبنيه، ثم يسجل الترحيلات في سجل Drizzle ويفحص أعمدة المخطط النهائي ودواله المطلوبة قبل إعلان النجاح. تُجرّب إعادة تشغيله للتأكد من عدم تكرار النقل. لا يبدأ النشر إذا فشل `db:check`؛ الفحص لا يطبّق أي ترحيلات.
5. نشر الكود ثم إعادة الدخول؛ الجلسات القديمة بلا `sessionVersion` تصبح غير صالحة. إغلاق صفحات المحرر القديمة وإعادة فتحها لأن عقود الحفظ تغيرت.
6. تعيين أصحاب المواد الإرثية من **خريطة معرفات مراجعة** عند الحاجة. لا نستنتج الملكية من الأسماء. يبقى للمشرف ذي `story.edit.any` الوصول حتى إتمام التعيين:
   ```bash
   node scripts/assign-story-owners.mjs --mapping=reviewed-owners.json
   node scripts/assign-story-owners.mjs --mapping=reviewed-owners.json --apply
   ```
   البنية: مصفوفة `{ "storyId": "…", "userId": "…" }`. المشغّل يرفض تغيير مالك موجود، ويحافظ على اسم الكاتب المنشور والرابط ويسجل كل تعيين.
7. تشغيل إنتاج Node بواسطة `npm start`؛ يبدأ خادم Next ومجدولًا داخليًا يفحص المواد المستحقة كل 5 ثوانٍ عبر loopback، دون الاعتماد على فتح لوحة التحكم. يولّد المشغّل سرًا عشوائيًا مشتركًا داخل الحاوية إذا لم يكن `CRON_SECRET` مضبوطًا، ولا يسجله. لا تستخدم `next start` مباشرة لأنه يتجاوز المجدول. في استضافة لا تشغّل سكربت Node، أو لإضافة عامل خارجي، اضبط `CRON_SECRET` نفسه و`SCHEDULER_ORIGIN` واستدعِ `npm run scheduler:tick` بوتيرة مناسبة؛ الطلبات غير المصرح بها مرفوضة. كل tick يعالج حتى 100 مادة مرتبة مع فحوص النشر وقفل النسخة لمنع التكرار، والتنظيف مرة في الساعة. الفحص الدوري ليس ضمانًا للنشر في الثانية نفسها؛ توقف الخادم أو تعطل قاعدة البيانات يؤخر التنفيذ، ثم تُعالَج المواد المستحقة عند التعافي. راقب أحداث `scheduler:started` و`scheduler:tick` و`scheduler:unavailable` مع فحص الصحة أدناه.
8. إعداد `TAHRIR_MFA_KEY` (مفتاح عشوائي 32 بايت ممثل بـ64 محرف hex) وحفظ نسخة آمنة منه. تغيير المفتاح دون ترحيل الأسرار يقفل حسابات MFA. يبدأ المسؤولون بتفعيل حساباتهم وحفظ رموز الاسترداد؛ لم نفرض التسجيل على حسابات غير مهيأة.
9. مراقبة `/api/health`: اكتمال أعمدة المخطط ودواله المطلوبة، ونجاح اتصال القاعدة وعدم وجود مواد مجدولة متأخرة أكثر من 5 دقائق. نقص المخطط أو عجز القاعدة أو تعطل الجدولة يعيد 503 دون كشف تفاصيل داخلية. استخدمه للمراقبة؛ لا تربط إعادة تشغيل الخدمة بتأخر الجدولة دون تمييز سبب التنبيه.
10. اختبار نشر مادة تجريبية في **بيئة الاختبار**، تعديلها، تعارض محررين، اعتماد/جدولة/استعادة، ودخول MFA، ثم التأكد من صور API في تطبيق iOS. النشر على الإنتاج وتوزيع إصدار iOS مرحلتان منفصلتان لم تنفذا ضمن هذه الجولة.

## التراجع

لا تحذف جداول التاريخ أو الأعمدة أو المحفوظات الجديدة. إن فشل التفعيل، أوقف الكتابات والعامل واحتفظ بقاعدة البيانات ونقطة الاستعادة. تصحيح أمامي هو الخيار المفضل. إعادة كود قديم مع السماح بالتحرير تعيد فجوة النشر؛ لا تُعد فتح الكتابات قبل إعادة التحقق من الحماية. استعادة قاعدة إنتاج كاملة قرار منفصل بسبب احتمال فقد كتابات أحدث.

## الأدلة والحدود

- بوابة `npm test`: lint وTypeScript وبناء معزول و184 اختبارًا ناجحًا. JavaScript مضغوط 183.4 KiB من حد 200 KiB. تحذير lint سابق واحد في `brand-mark.tsx` بشأن وسم الصورة، بلا أخطاء.
- تكامل PostgreSQL: 20 حالة ناجحة، تتضمن الحالات المتزامنة المذكورة أدناه. تجربة dump/restore طابقت بيانات 25 جدولًا. نجح بناء iOS للمحاكي دون توقيع.
- فحص HTTP محلي: GET الجدولة يعيد 405، وPOST بلا مفتاح 401، وفشل القاعدة في الجدولة والصحة والنشرة 503. المحفوظات بلا عضوية 401. أربع صور من مخرجات Mobile API استُرجعت بنجاح 200 ونوع `image/*`.
- فحص المتصفح: المقال بعرض 320 و390 و1440 بكسل، والرئيسية بعرض 320 و1440؛ بلا تمدد أفقي. عمود المقال 288 بكسل عند عرض 320، و358 عند عرض 390، وعمودان على سطح المكتب. اختبار الحسابات والكتابات أُجري في القاعدة المعزولة وليس على حسابات الإنتاج.
- فحص الاعتماديات النهائي `npm audit`: صفر ثغرات معروفة وقت الفحص، شامل اعتماديات التطوير، بعد تحديث محدود لـ`fast-uri` إلى 3.1.7 و`qs` إلى 6.16.0. هذه نتيجة قاعدة التنبيهات وليست ضمانًا أمنيًا شاملًا.
- `tests/migration-adoption.integration.mjs`: ينشئ قاعدة اختبار مستقلة من مخطط الأساس القديم، ويثبت فشل الجاهزية قبله ونجاحها بعد الترحيلات، مع بقاء كلمة المرور والمحتوى والرابط والمحفوظات وإمكانية إعادة التشغيل. يحذف قاعدة الاختبار الخاصة به بعد الانتهاء.
- `tests/workflow.integration.mjs`: قاعدة `alelm_test*` فقط، يطبق الترحيلات مرتين، ويختبر مسار الدخول الفعلي والجلسة الموقّعة ورفض الجلسة الملغاة وطلب MFA وفحص الصحة، إضافة إلى الكتابة والنشر المتزامن وCAS والحجز والمحفوظات والنشرة. يستخدم PostgreSQL عبر TCP ويقلد معاملة `neon-http.batch`؛ اختبار البيئة المرحلية على Neon HTTP يبقى ضمن بوابة التفعيل.
- `tests/totp.test.mjs`: متجهات SHA-1 المنشورة في [RFC 6238 Appendix B](https://www.rfc-editor.org/rfc/rfc6238#appendix-B)، بما فيها تواريخ بعد 2038، وعزل تشفير السر بالحساب والغرض.
- `scripts/test-restore.mjs`: dump/restore لقاعدة الاختبار فقط، ومطابقة بصمة بيانات كل جدول، مع حذف النسخة المؤقتة بعد الفحص.
- المراجعة الأمنية المستقلة اكتشفت 4 حالات؛ أُغلقت بتوحيد طول كلمة المرور وCAS، وإخراج تعارض الجدولة إلى المراجعة، وإزالة كاش العضو العام وربط طلبات الحفظ بالحساب. توجد اختبارات تنفيذية للحدود الخادمية؛ لم يُختبر تبديل حسابي عضوية حقيقيين داخل متصفح أو جهاز iOS ضد الإنتاج.
- لا تشغيل للنماذج المدفوعة، ولا إرسال بريد، ولا تجربة MFA على حساب حقيقي، ولا ادعاء نشر إنتاجي.

## الاحتفاظ بالبيانات

تنظيف ساعي يعمل من نبضة المجدول (`/api/tahrir/tick`) في `lib/tahrir/retention.ts`، على دفعات من 2,000 صف (حتى 25 دفعة في التشغيلة) لتجنب الأقفال الطويلة، وقابل لإعادة التشغيل بلا أثر. كل تشغيلة تسجل حدث `scheduler:retention` بأعداد المحذوف؛ فشل التنظيف لا يوقف النشر المجدول.

## حزمة المحرر — 9 سبتمبر 2026 (سلوك تشغيلي مستجد)

- مسودة الحارس موحدة في مواضع الفحص الخمسة (`lib/tahrir/guard-draft.ts`): الفحص الحي وطلب الاعتماد والنشر والجدولة وترقية المجدول تحمل كلها `breaking` من `breaking_until` و`sourceUrls` من روابط المتن المطلقة. النتيجة العملية: مادة موسومة «عاجل» بلا مصدر معتمد تظهر لها `BREAKING-SOURCES`، ومصدر أجنبي في مادة عن المقامين يظهر له `ROYAL-FOREIGN-SOURCE` — كانت هذه القواعد عمياء قبل الحزمة.
