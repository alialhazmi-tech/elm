# خدمة وصول وكلاء «العلم» — معاينة مستقلة

هذه حزمة اختبار منفصلة لتجربة OAuth و`auth.md` وتسجيل الوكلاء. تدعم البحث وقراءة الأخبار العامة فقط. ليست موصولة بحسابات أعضاء الموقع أو التحرير، ولا تملك اتصالًا بقاعدة بيانات الموقع.

**حالة النشر: محلية فقط.** دمج ملفات هذه الحزمة لا يضيف مسارات إلى Next.js ولا يشغّل الخدمة في Railway. تشغيلها في الإنتاج يحتاج مراجعة ونشرًا مستقلين؛ نقطة التشغيل ترفض `NODE_ENV=production` وتستمع على `127.0.0.1` فقط. لم يتغير DNS أو DNSSEC أو Cloudflare.

## التجربة المحلية

تحتاج Node.js 24.13 أو أحدث ضمن الإصدار 24. الحزمة لها lockfile خاص بها.

```sh
cd services/agent-access
npm ci --ignore-scripts
npm test
npm run test:browser # يتطلب Chrome مثبتًا؛ أو حدد CHROME_PATH
npm run demo
```

افتح `http://127.0.0.1:4318`. التجربة تنشئ قاعدة SQLite مؤقتة ومحتوى أخبار اصطناعيًا وحساب مالك اختبار منفصلًا. تعرض الطرفية **مسار ملف** بيانات الحساب فقط؛ الملف محلي بصلاحية `0600`. لا ترفعه أو تشاركه. أوقف التجربة بـCtrl+C واحذف المجلد المؤقت الذي طُبع مساره عند الانتهاء.

`npm start` يستخدم تخزينًا محليًا دائمًا في `data/agent-access.sqlite` ويقرأ واجهة الأخبار العامة عبر HTTPS عند طلب خبر. لا يتصل بقاعدة بيانات الموقع. للتجربة دون أي اتصال بالموقع استخدم `npm run demo`.

| المسار | الوظيفة |
|---|---|
| `/.well-known/oauth-authorization-server` | تعريف OAuth ومنح JWT bearer وclaim المنفذة فقط |
| `/.well-known/oauth-protected-resource/api` | تعريف مورد `/api` وصلاحية `news:read`؛ نسخة أيضًا عند المسار الأساسي |
| `/.well-known/jwks.json` | مفتاح التحقق العام فقط |
| `/auth.md` | خطوات التسجيل والقراءة والربط والإلغاء القابلة للتنفيذ |
| `POST /agent/identity` | تسجيل وكيل مجهول وإصدار assertion صالحة 24 ساعة |
| `POST /oauth2/token` | إصدار access token لمدة لا تتجاوز خمس دقائق |
| `GET /api/search` و`GET /api/articles/:id` | قراءة الواجهة العامة عبر مفتاح الخدمة |
| `POST /api/mcp` | MCP Streamable HTTP بأداتي `search_articles` و`read_article` |
| `/agent/identity/claim` و`/claim` | ربط اختياري بحساب مالك اختبار مستقل وموافقة بشرية |
| `POST /oauth2/revoke` | إلغاء مفتاح واحد؛ التسجيل يبقى فعالًا |
| `/owner/revoke` | إلغاء التسجيل وكل مفاتيحه بعد تحقق المالك |
| `/health` | فحص تشغيل الخدمة وتخزينها فقط |

القراءة تعمل قبل ربط المالك وبعده بالصلاحية نفسها. الربط ليس تسجيلًا بعضوية «العلم» ولا تأكيدًا لبريد إلكتروني؛ هو ربط بحساب اختبار أنشأه مشغّل هذه الخدمة. لا توجد رسائل بريد أو تسجيل مالك ذاتي أو موفرو هوية خارجيون.

## إدارة حساب الاختبار والإلغاء

أنشئ كلمة مرور عشوائية فريدة لا تقل عن 16 حرفًا. مررها من مدير كلمات المرور إلى stdin، وليس وسيطة في سطر الأوامر أو ملفًا داخل Git:

```sh
# تدفق stdin يأتي من مدير كلمات المرور؛ لا تكتب السر داخل هذا الأمر.
npm run admin -- create-owner owner@example.test
npm run admin -- revoke REGISTRATION_ID
```

أمر إنشاء الحساب يرفض الإدخال المباشر المرئي في الطرفية. لا يستبدل حسابًا موجودًا. المتغير `AGENT_DATA_FILE` يحدد ملف تخزين مستقلًا عند الحاجة؛ يجب أن يكون داخل مجلد خاص بهذه الخدمة. `AGENT_PORT` افتراضيًا 4318، و`AGENT_ISSUER` افتراضيًا عنوان loopback لذلك المنفذ. لا تُضبط أي متغيرات تخص Neon أو CMS.

## حدود الأمان والتوافق

- مفاتيح Ed25519 موقّعة بمكتبة `jose`، مع تحقق النوع والمصدر والجمهور والصلاحية والإصدار والانتهاء. المخزن يحتفظ بالمفتاح الخاص؛ يتطلب قرصًا خاصًا وحماية النسخ الاحتياطية.
- التسجيلات وclaims والإلغاء باقية في SQLite بعد إعادة التشغيل. يتم حفظ hashes لرموز claim والإلغاء، وكلمات مرور المالك باستخدام scrypt مع salt مستقل. لا تظهر كلمات المرور أو المفاتيح أو البريد أو cookies في سجل التطبيق.
- إلغاء التسجيل يبطل المفاتيح الحالية ويمنع إصدار غيرها. إلغاء access token وحده لا يلغي assertion. اكتمال الربط يغيّر إصدار التسجيل ويبطل جميع مفاتيحه السابقة.
- ربط المالك يتطلب كلمة مرور مستقلة وCSRF وOrigin مطابقًا ورمزًا من الوكيل. صلاحية محاولة الربط عشر دقائق وخمس محاولات رمز فقط. لا يمكن تغيير بريد المحاولة أو إعادة ضبط محاولاتها. بعد فشل دخول المالك عشر مرات يقفل الحساب 30 دقيقة.
- لا توسعة صلاحيات بعد الربط. لا توجد كتابة للمحتوى، ولا رفع ملفات، ولا وصول إلى `/api/viewer` أو `/tahrir` أو أي مسار خاص. قراءة المصدر محصورة في `https://alelm.net/api/content/v1/...`، دون تمرير credentials أو cookies أو السماح بتحويلات HTTP.
- الطلب 16 KiB، استجابة المصدر 2 MB، مهلة المصدر خمس ثوانٍ. خمس تسجيلات/IP/دقيقة، 1000 تسجيل فعال، انتهاء وحذف بعد 24 ساعة؛ 30 قراءة للمصدر/دقيقة وأربع قراءات متزامنة على مستوى العملية كلها. لا تُوثق عناوين IP في logs. لا نثق بترويسات forwarded لتجاوز الحدود.
- الوضع المدعوم عملية واحدة وقرص SQLite محلي دائم. حدود الذاكرة ليست موزعة؛ تعدد النسخ أو تشغيل خلف proxy عام يحتاج تصميم حدود مشتركة والتحقق من عنوان العميل. لا تكفي هذه المعاينة لنشر متعدد النسخ.
- OAuth هنا ملف JWT bearer وفق RFC 7523؛ امتداد claim خاص بمشروع auth.md. لا ندّعي OIDC أو authorization-code/PKCE أو federation أو تسجيل عملاء RFC 7591. عميل MCP يتصل بمفتاح تم إصداره من هذا التدفق؛ تدفق تسجيل الدخول الآلي في عملاء MCP الذين يشترطون authorization-code/PKCE ليس منفذًا.
- نتيجة claim تسلّم مرة واحدة؛ إن انقطع الاتصال وفُقد الرد بعد التسليم، يلزم تسجيل وكيل جديد. لا refresh tokens أو استرداد مالك عبر البريد في هذه المعاينة.
- يمكن للوكيل المجهول إنشاء تسجيل آخر ضمن الحدود؛ الإلغاء يمنع استخدام التسجيل الملغى، وليس حظر هوية إنترنت مجهولة نهائيًا.

## الاختبارات والتحقق

`npm test` يشغّل 23 اختبارًا محليًا ببيانات مصطنعة، بما فيها عميل MCP الرسمي، وتحقق التواقيع والصلاحيات والانتهاء، وتنافس الموافقة، وCSRF، وحدود التسجيل، واستمرار الإلغاء بعد إعادة التشغيل، ومنع تسريب credentials إلى المصدر. `npm run test:browser` يختبر الموافقة والإلغاء في Chrome فعلي ويؤكد وجود Origin وعدم إرسال رابط التحقق ضمن Referer. لا تحتاج أي أسرار أو صلاحيات إنتاج. CI مستقل على Node 24 يشغّل التثبيت وتدقيق التبعيات والاختبارات واختبار المتصفح، وتبقى بوابة جودة الموقع كما هي.

## ما يلزم قبل نشر مستقل لاحقًا

1. اعتماد نطاق خدمة مستقل وخطة تشغيل وتخزين ونسخ احتياطي **لهذه الخدمة فقط**، مع تجربة استعادة ومدة احتفاظ واضحة.
2. مراجعة أمنية لدورة التسجيل والموافقة ومفتاح التوقيع، وخطة تدويره وإعادة إصدار credentials. التوقيع الحالي ثابت عبر إعادة التشغيل ولا توجد واجهة تدوير بعد.
3. إعداد HTTPS وحدود الحافة وعزل الشبكة والمراقبة، دون تغيير تسجيل دخول الموقع. تحويل HTTP المحلي مسموح للتجربة فقط؛ تشغيل عام يتطلب HTTPS فعليًا.
4. تحديد عملاء الوكلاء المستهدفين وتجربتهم. إضافة authorization-code/PKCE إن احتاجت تلك التطبيقات ذلك، كتغيير مستقل مدروس.
5. بعد اعتماد النشر فقط: نشر الخدمة المستقلة، ثم إضافة روابط اكتشاف صحيحة من موقع العلم إليها وفحصها خارجيًا. ملفات المعاينة لا تجعل النطاق العام يعلن خدمة لم تُنشر.

التراجع عن هذه المعاينة: إيقاف عمليتها. التراجع عن الملفات: revert للـPR. لا توجد migration على قاعدة الموقع ولا تغيير DNS يحتاج استرجاعًا.
