# أدوات قراءة المحتوى العام: MCP وWebMCP وARD

التاريخ: 14 أكتوبر 2026. مبني على `main` عند `7a33a7c03f9a0ea4c6538c92ed009bbefaa12d62`.

النطاق المعتمد: البحث وقراءة الأخبار المنشورة للعامة فقط. DNS-AID وDNSSEC للمرحلة الأخيرة. لا توجد واجهة نشر أو حسابات أو صلاحيات تحرير أو هجرة قاعدة بيانات أو تغيير إعدادات الاستضافة ضمن هذا التغيير. هذه نتائج فرع الاختبار وليست دليل نشر على الإنتاج.

## التنفيذ

| البند | ما أضيف | الحالة |
|---|---|---|
| MCP | `/mcp`، نقل Streamable HTTP، أداتا `search_articles` و`read_article` | منفذ ومختبر محليًا بعميل SDK الرسمي |
| بطاقة MCP | `/mcp/server-card` وفق مخطط SEP-2127 الحالي؛ مسار قديم منفصل للتوافق مع الفاحص | المخطط الرسمي اجتاز التحقق، وحقول الهوية متطابقة مع الاتصال |
| ARD / AI Catalog | `/.well-known/ai-catalog.json` يعلن عن خدمة MCP ووصف OpenAPI ومهارة القراءة الموجودة | روابط حقيقية ومحتوى عام؛ MIME الحالي وCORS مفتوحان لملفات الاكتشاف فقط |
| WebMCP | الأداتان في الرئيسية والبحث وقالب الأخبار، مع اكتشاف الدعم وإلغاء التسجيل عند مغادرة الصفحات | تحقق أصلي في Chrome، مع تفعيل الميزة؛ لا يُدّعى دعم جميع المتصفحات |
| حدود الاستخدام | MCP وREST العام يتشاركان حارس تحميل محدودًا داخل عملية الخادم | 60 طلبًا/IP موثق/دقيقة، 600 إجمالًا، 8 متزامنة، و429 مع Retry-After |
| DNS-AID وDNSSEC | لا تعديل | مؤجلان حسب طلب المالك |
| OAuth وauth.md | لا إضافة | لا حاجة لهما لهذه الأدوات العامة |

## حدود الصلاحيات والبيانات

- الأدوات تسمي عمليتين فقط؛ لا تقبل SQL أو اسم جدول أو عنوان URL للجلب أو معلمات تعديل.
- تستخدم قارئ المحتوى العام الذي يفلتر المنشور والتاريخ وإصدارات المراجعة والحقول العامة؛ لا تعتمد على هوية عضو أو محرر.
- لا توجد أدوات نشر أو حذف أو تعديل أو رفع ملفات أو قراءة حسابات. الاختبار يحاول طلبها ويتحقق من رفضها.
- نصوص الأخبار تعاد كمادة مصدرية مع توجيه للاستشهاد بالرابط المعتمد. WebMCP يعلنها كبيانات غير موثوقة كتعليمات.
- يرسل WebMCP طلبات GET مع `credentials: omit` ولا يرسل cookies؛ يتحقق من المعرف والمدخلات قبل الجلب، ولا يتبع التحويلات.
- لا تتجاوز الخدمة حارس أصل Railway. Origin غير المسموح مرفوض في MCP؛ الطلبات المباشرة بدون Origin ممكنة للمساعدات.
- حد جسم MCP هو 16 KiB فعليًا أثناء القراءة، لا اعتمادًا على Content-Length فقط. مهلة القراءة 10 ثوان، والطلبات المجمعة مرفوضة.
- لا توجد جلسات MCP محفوظة أو SSE مستقل. استجابات MCP لا تُخزّن. GET/DELETE على نقطة MCP يعيدان 405.
- كود قياس الصفحات بقي كما هو داخل حد عميل واحد مشترك لتجنب زيادة HTML؛ منطق WebMCP مستقل ولا يرسل أحداث Analytics.

## أدلة التحقق

1. `npm test`: نجحت lint وtypecheck وبناء الإنتاج و**498 اختبارًا** وميزانيات الأداء. تحذير lint واحد سابق في صورة العلامة التجارية.
2. `npm run test:integration` ثم اختبارات RSS والمحتوى وHTTP: نجحت على PostgreSQL 17 محلي معزول ومهاجر. لم تُستخدم قاعدة الإنتاج.
3. اتصال MCP بعميل SDK الرسمي: التهيئة وقائمة الأدوات والبحث وقراءة مادة فعلية من قاعدة الاختبار؛ المسودات والمراجعات والمجدول والمستقبل والمؤرشف والمواد غير المؤهلة مخفية. الأدوات غير المعلنة والمعلمات غير المسموحة مرفوضة؛ فشل المصدر يعاد كخطأ دون تفاصيل خاصة.
4. HTTP مع بناء الإنتاج: بطاقة الخدمة والفهرس وMIME/CORS، حارس الأصل، Origin، الطلب الكبير والمجمّع وJSON غير الصالح، GET/DELETE، خطأ التخزين، وحصة الطلبات المشتركة. الصفحة العادية تبقى متاحة عند استنفاد حصة الأدوات.
5. اختبار وحدة للقارئ يتحقق من الطلب المتدفق الكبير والطلب البطيء وإلغاء القراءة. اختبارات WebMCP تتحقق من عدم إرسال credentials، وفحص المدخلات قبل الشبكة وإلغاء الطلب عند مغادرة الصفحة.
6. Chrome **155.0.8059.41** مع `--enable-blink-features=WebMCP`: ظهرت الأداتان في `document.modelContext.getTools()`، ونفذت قراءة عبر `executeTool` باستخدام GET دون cookies رغم وضع cookie اختبار. رُفض معرف URL، ولم تظهر أدوات على صفحة التحرير، ولم تظهر أخطاء JavaScript في العينة. استجابة المقال في هذا الاختبار وحده fixture؛ فلترة قاعدة البيانات اختُبرت منفصلة. الدليل: [browser JSON](public-agent-tools-browser.json).
7. بطاقة الخدمة اجتازت مخطط JSON Schema الرسمي للامتداد (المرجع أدناه) باستخدام Ajv 2020.

القياس المحلي لبناء التحقق: HTML الرئيسية **30,701 بايت gzip** تحت سقف 30KiB، وJavaScript الرئيسية **196.4KiB** تحت 200KiB. لم تُرفع الميزانيات. هذه أحجام موارد وليست قياس LCP أو نتيجة حقل.

## الاعتماديات والمخاطر المتبقية

أضيف SDK الرسمي `@modelcontextprotocol/sdk@1.32.1` مع تثبيت Zod على الإصدار الموجود سابقًا `4.4.3`. تم تحديث `proxy-addr` إلى `2.0.8` و`fast-uri` إلى `3.1.8` لمعالجة تنبيهين في شجرة الاعتماديات المرتبطة.

المقارنة الحالية لـnpm audit: **14 تنبيهًا على main قبل التغيير → 12 بعده**، ولا أسماء حزم جديدة متأثرة بحسب المقارنة. ما زالت توجد تنبيهات سابقة: 11 عالية وواحد حرج مرتبط بـNext.js. لم يُنفذ تحليل استغلال شامل أو ترقية إطار العمل ضمن هذه الدفعة؛ يلزم تتبع مستقل لهذه التنبيهات. نجاح CI ليس شهادة خلو كامل من الثغرات.

حدود التحميل داخل العملية، وليست حصة موزعة بين جميع النسخ أو ضمانًا ضد هجوم موزع. وقد يتشارك عدة عملاء عنوان IP واحدًا. يلزم متابعة الاستخدام بعد النشر وضبط Cloudflare عند الحاجة. WebMCP واكتشاف الخدمات يتطوران؛ لا يعني اجتياز الفاحص ضمان الاستشهاد أو الاكتشاف التلقائي لدى كل مساعد.

## المطابقة بين المواصفات والفاحص

تعليمات الفاحص القديمة تطلب `serverInfo` و`endpoint` و`capabilities` على `/.well-known/mcp/server-card.json`. مواصفة SEP-2127 الحالية تجعل البطاقة عند عنوان مثل `/mcp/server-card` بهوية `name/version` و`remotes`، وتستبعد إعلان الأدوات والقدرات من البطاقة الساكنة. لذلك البطاقة المعتمدة تتبع المواصفة الحالية، ووثيقة التوافق القديمة منفصلة وتصف الخادم نفسه بصدق. قائمة الأدوات تؤخذ أثناء الاتصال عبر `tools/list`.

لا تُضاف بطاقة لخادم غير عامل أو مسارات مصادقة وهمية لرفع درجة الفاحص. يُعاد الفحص الخارجي على الإنتاج بعد الموافقة على الدمج والنشر فقط.

## التحقق بعد النشر والتراجع

- فحص الاكتشاف وLink عبر Cloudflare، ثم اتصال MCP وبحث وقراءة خبر منشور.
- إعادة فحص HTML وMarkdown و/api/viewer والحماية وحالة الجاهزية، ثم فحص WebMCP في متصفح داعم.
- إعادة isitagentready وحفظ النتيجة؛ DNS والمصادقة خارج النطاق الحالي ويظلان غير منفذين.
- التراجع بعكس التزام هذه الدفعة وإعادة النشر، أو الرجوع لنشر Railway السابق مؤقتًا. لا هجرة بيانات أو أسرار جديدة أو إعداد DNS يحتاج للعكس.
